## 二、T1 预约演示表单端到端（用户问题 #1）

**测试路径**：浏览器真实操作（非 curl 模拟）——官网首页滚到底部 → 逐字段键入（学校名称/姓名/电话/需求）→ 点击「预约演示」→ 前端提示「感谢！我们会尽快联系您。」→ 超管登录调 `GET /leads` → Postgres 直查。

**证据链**：

| 环节 | 结果 |
|---|---|
| 前端提交 | `form-tip ok`：「感谢！我们会尽快联系您。」 |
| API 接收 | `GET /leads`（Bearer token）返回 id=22，company=测试中学T1，name=测试员，phone=13800001111，message=T1端到端链路测试，createdAt=当日 |
| DB 直查 | `SELECT COUNT(*) FROM "Lead"` = 10（含该条），与 API `total:10` 一致 |

**结论**：`SiteLeadForm → POST /leads/public → Prisma lead.create → Postgres` 全链路通畅，管理后台「咨询留资」页可见。

> 附带发现并修复（已入 `cc98075`）：site-config 接口返回 `contactPhone/workHours/wechatName: null` 时覆盖前端兜底默认值，导致联系方式区三行空白。已改为 merge 前剔除 null/空串。

| API 鉴权 | ✅ | 无 token 访问 /leads 正确返回 2001「未登录」；superadmin 登录→Bearer 访问通过 |
| 站点配置 API | ✅ | GET /site-config/public 返回 schoolsCount=5/studentsCount=366/costSave=推广期（官网数据区渲染一致） |
| 前端构建链 | ✅ | dev server 全程无编译错误；console 无运行时错误（多次截图会话验证） |

**测试中顺带发现**：
1. Postgres 容器角色名非 `aiteacher`（`psql -U aiteacher` 失败），实际由容器环境变量决定——运维文档可补一句连接串说明。
2. `Lead` 表无 `updatedAt` 列（Prisma schema 用 createdAt only）——直写 SQL 时注意。
3. `leads.create` 无 DTO/class-validator 校验，恶意超长字符串可入库——建议后续加 ValidationPipe + dto（非阻断）。
