课堂实时流程：举手答疑 & 纪律警告
都是课中副线：摄像头+麦克风实时感知，虚拟人物当场反应，事后写入档案
🙋 流程一：学生举手提问
✋
学生举手
不懂就举手
→
📷
识别举手动作
视觉模型检测举手姿势
→
😊
认出是谁
人脸对到花名册
→
🧑‍🏫
虚拟人转向他
"XX，你哪里不懂？"
→
🎤
学生说出问题
收音→语音转文字
→
🧠
AI 现场解答
结合本课内容讲解
→
✅
确认懂了
"懂了吗？"→ 回到主课
边界规则：多个学生同时举手 → AI 按"谁先举的/谁被点名过最少"决定先问谁；学生说不清楚 → 再追问一次；问题与本课无关 → "这个我们课后辅导时间讨论"，不打断主课。
⚠️ 流程二：违纪检测与警告
👀
检测异常
大声说话/走动/离座/睡觉
→
😊
认出是谁
人脸对到花名册
→
📏
判定违纪类型
规则引擎：按类型扣分（PRD §10.2）
→
🧑‍🏫
当场警告
"XX，请注意纪律，本次违纪扣 X 分"
→
📝
记入纪律日志
谁、何时、什么违纪、扣几分
→
📊
课后算分
计入该生本节课表现
按类型扣分（PRD §10.2，管理员可配）：大声说话 -5、离座/走动 -3、睡觉/趴桌 -8、旷课 -20、迟到 -5、全勤 +5；警告按次数升级：第 1 次口头警告（不额外扣分）、第 2 次通知家长、第 3 次通知管理员——扣分始终按违纪类型执行，升级规则只影响话术与通知。警告语气由虚拟人物当面说出口，不是弹窗——学生能听到 AI 老师在点名批评自己。
这两个流程都依赖的三件事
👁 持续视觉监测
整节课摄像头一直跑，随时检测举手/走动/睡觉/离座
👤 人脸↔花名册绑定
不管是举手还是违纪，第一步都是"认出是谁"，所以人脸库必须先建好
📏 规则引擎
警告几次、扣几分、怎么措辞——这些规则由管理员在后台配，不写死在代码里
