## 一、产品概述

**AI Teacher** 是一款替代教师完成教学与辅导工作的智能 Agent 产品。它能在指定时间自动给班级上课，通过摄像头和麦克风感知课堂，用虚拟数字人站在投影前讲课，同时实时识别学生举手、维持纪律、布置批改作业，并持续为每个学生生成评估报告。

**目标客户**：K12 学校、培训机构、私立学校。
**商业模式**：SaaS 订阅制——客户在官网联系你，你开通订阅后，客户在校内装一个客户端软件，软件连你的云端获取核心 AI 服务。

## 二、角色体系

| 角色 | 在哪用 | 核心权限 |
|---|---|---|
| **Super 管理员（你/总部）** | 你的云后台 | 开通/关闭学校订阅、看全校用量、管所有学校 |
| **学校管理员** | Web 管理后台（浏览器） | 本校排课、传教材、管教师、看本校数据 |
| **年级×科目代表老师** | Web 后台/小程序教师模式 | 管本年级本科的教室、Agent、作业审批 |
| **授课 Agent** | 云端运行 | 一班一科一个，按课表自动上课 |
| **辅导 Agent（全能型）** | 云端运行 | 跨科目随身答疑 |
| **学生** | 微信小程序学生模式 | 交作业、看自己成绩、请假 |
| **家长** | 微信小程序家长模式 | 实时看自己孩子上课、看成绩排名 |

## 三、核心功能模块

### 3.1 课堂教学

- **定时上课**：按课表到点自动启动，时长可配。
- **数字人授课**：投影上显示 PPT + 虚拟数字人（2D Live2D 风格），按讲稿讲、TTS 口型同步、预设手势。
- **预制+实时混合**：课前 AI 自动做 PPT 和讲稿，课中数字人按稿讲，同时实时听看学生、即兴点名提问。
- **人脸识别点名**：摄像头识别全班人脸，对应花名册姓名。
- **举手识别**：学生举手 → 摄像头识别 → 人脸确认 → 数字人转向他问"哪不懂" → 收音 → AI 现场解答。
- **多 Agent 并存**：一班一科一个授课 Agent，各自按自己课表跑，不冲突。

### 3.2 纪律与考勤

- **实时检测**：整节课摄像头+麦克风持续识别——大声说话、走动、离座、睡觉、旷课。
- **当场警告**：数字人当面开口警告（"XX，第一次警告，再犯扣 X 分"），不是弹窗。
- **升级规则**：管理员可配——第几次警告、扣几分、什么时候通知管理员。
- **请假管理**：学生小程序申请 → 管理员审批 → 已请假学生不被提问（避免 bug）。
- **考勤记录**：迟到/早退/旷课/请假自动记入，课后算分。

### 3.3 辅导（全能 Agent）

- 学生戴智能眼镜（看）+ 手表/耳机（听说），AI 随身实时答疑。
- 辅导流程复用课堂能力，但终端从教室主摄像头换成学生穿戴设备。
- 辅导结束后同样出即时评估。

### 3.4 作业系统

- **作业类型**：
  - **课中作业/提问**：在上课屏幕浮层弹出，学生口头答/举手，AI 当场点评，不进小程序。
  - **课后作业**：推送到小程序，学生拍照/文字提交。
- **作业流程**：
  1. AI 生成作业草稿（或管理员手动布置）
  2. 管理员确认后才下发（不是每节课必有作业）
  3. 推送小程序，写明：哪个班、哪科、交什么、截止时间
  4. 学生小程序拍照提交
  5. AI 批改出初评
  6. 管理员复核
  7. 成绩回写数据库，学生可看
- **小程序不直连 Agent**，只和数据库打交道。

### 3.5 学期教学日历

- 年级科目代表老师上传：本学期时间表、电子版教材、考试安排（月考/段考/期末）。
- AI 自动：拆教材→教学大纲→排每天上哪节→定月考范围→生成每课 PPT 和讲稿。
- 到点自动开课。

### 3.6 评估与报表

- **每节课后**：自动给每个学生打表现分（课堂参与、纪律、作业、举手答题）。
- **辅导后**：即时评估。
- **综合评估**：结合历史成绩，对每个学生生成个人分析报告。
- **输出**：表格 + 图表 + 个人报告，含排名、趋势。

### 3.7 小程序三模式

**学生模式**：作业（看/交/看批改）、自己表现分、进度、考勤、请假、辅导历史。只看自己。

**家长模式**：
- 实时看课（孩子所在教室直播画面 + 上课内容）
- 孩子实时状态
- 表现分、班级/年级排名
- 作业完成情况、考勤记录
- 成绩趋势图
- 只能看绑定的孩子

**教师/管理员模式**：
- 全班实时看课
- 全班考勤纪律
- 作业待审批列表、手机批请假
- 全班成绩分布、每个学生个人报告
- 重操作（排课/传教材）仍在 Web 后台

### 3.8 校级驾驶舱与教学质量监控（校长视角）

- **全校总览大屏**：今天上了多少节课、出勤率、整体成绩趋势、哪个班哪个科目薄弱，一屏看清。
- **教学质量分**：每节课自动算互动率、学生注意力分布、作业完成率、举手频次，给课程质量打分。
- **跨班跨科对比**：一班 vs 二班数学成绩、各班语文课堂参与度横向对比表。

### 3.9 考试全流程

- **AI 监考**：考试期间摄像头监控作弊行为，自动识别并记录。
- **成绩录入**：客观题自动判分，主观题 AI 初评+老师复核。
- **考后分析**：全校平均分、及格率、知识点薄弱项、与上次考试对比。

### 3.10 学生预警

- 成绩突然下滑、连续缺课、课堂参与度暴跌等异常，系统自动标红。
- 主动推送给对应老师和家长，不用校长自己翻报表。

### 3.11 成本 ROI 与合规审计

- **成本 ROI 报表**：自动统计用 AI 老师后节省的教师人力成本、生均成本变化，给董事会看。
- **合规留痕**：上课录像、AI 警告记录、学生处分全程可审计，教育局检查可调取。

### 3.12 设备运维告警

- 教室摄像头故障、麦克风无声、小盒子离线等异常，自动通知后勤维修。
- 设备状态仪表盘：在线/离线/故障一目了然。

### 3.13 学校品牌定制

- 课件、小程序、投影画面显示学校 logo 和校名。
- 数字人形象、配色可按学校定制。

### 3.14 真人老师工作量管理

- 学校真人老师（管理员）复核作业、批请假的工作量自动统计。
- 年级主任可看每个老师本周复核量、审批时效，作为绩效考核参考。

### 3.15 临时调课与代课

- 运动会、放假、设备故障等临时情况，支持调课、补课、临时停课。
- 调课后 AI 自动按新课表执行，不误开课。

### 3.16 家校主动通知

- 系统按情况自动推送给家长："明天月考请复习第三章""您孩子今天课堂表现下滑"。
- 不需要老师再手动群发通知。

### 3.17 学科题库与命题

- 学科老师可导入自己的历年题、好题、自编题，按知识点/难度/标签分类。
- 本周作业可从题库挑选，或指定 AI 参考题库出题。
- 支持题库版本管理，按学期更新。

### 3.18 主观题复核工作台

- 作文、论述题等主观题，AI 批改后进入复核队列。
- 老师在专门界面逐条查看：AI 打分、AI 评语 → 改分、写评语、通过。
- 批改进度、待复核数量一目了然，作为工作量统计依据。

### 3.19 学科专项练习

- **语文**：课文朗读打卡（学生录语音，AI 评发音流利度）、古诗默写拍照批改、背诵抽查。
- **英语**：口语跟读、单词听写。
- **数学**：错题自动归集本，考前针对推送。
- 各科目特有的练习形式，不局限于通用作业。

### 3.20 学科教研报表

- 只看本科本年级：各班平均分、及格率、知识点整体薄弱分布、班际对比。
- 不出现其他科目、其他年级数据。

### 3.21 AI 教学风格与节奏可调

- 学科老师可按科目调 AI 上课参数：讲解快慢、互动频率、语气严肃/温柔/幽默、提问难度。
- 调整后该科目所有班级 AI 老师按新风格授课。

### 3.22 组卷审卷

- 月考/期中/期末卷，AI 按教学进度和知识点出题。
- 老师在后台审卷：改题、换题、调难度、定分值，然后锁卷。
- 锁卷后到考试时间自动分发，AI 监考。

### 3.23 教学进度一键微调

- 运动会、放假、设备故障导致缺课，老师点"整体后挪 N 天/周"，后续课表、作业、考试自动顺延。
- 支持单科调整，不影响其他科目。

### 3.24 巡课旁听

- 学科老师随时点开本班/本年级任意一节 AI 课旁听，看 AI 授课质量和学生互动。
- 旁听不影响正常上课，不打扰学生。

### 3.25 学生学科薄弱画像

- 每个学生该学科哪些知识点薄弱（如"一元一次方程总是错"），自动标记。
- AI 辅导时针对性补弱；老师可看全班薄弱知识点分布。

### 3.26 学生表现与班级表现模块

**课堂环境感知（视频+音频双通道）：**
- **个人行为检测**：睡觉、趴桌、走动、离座、举手、低头看手机，摄像头持续识别。
- **课堂嘈杂度**：麦克风持续监测教室整体环境音水平，生成"这节课安静/嘈杂/失控"的氛围标签。
- **睡觉归因**：学生趴桌/睡觉时，不只记违纪，还结合他当天出勤、过往作息、近期成绩，标记"疑似熬夜/身体不适/真正违纪"，不同情况走不同流程——身体不适通知家长，违纪按纪律规则处理。
- 所有课堂音视频事件按时间线留存，可回看。

**学生表现模块（个人维度）：**
- 综合视图：出勤率、纪律事件次数与扣分、课堂参与（举手/发言）、作业完成率、各科成绩趋势。
- 一句话画像："本周课堂状态：积极，作业完成好，数学需加强。"
- 时间轴：这学期每次课堂表现、每次违纪、每次进步。
- 异常自动预警（联动 3.10）。

**班级表现模块（班级维度）：**
- 全班出勤率、平均纪律分、课堂氛围评分（基于嘈杂度和举手频次）。
- 班际对比：平行班谁课堂氛围好、谁纪律差。
- 一节课一张"班级课堂报告"：今天氛围如何、违纪几次、互动几次。

**年级表现模块（年级主任视角）：**
- 本年级所有班级的出勤率、纪律分、平均分、课堂氛围汇总。
- 年级排名：各班成绩排序、进步最快/退步最明显的班。
- 年级整体薄弱知识点、年级纪律事件趋势。
- 衔接校级驾驶舱和班级表现，中间这一层。

### 3.27 学生个人中心（学生视角）

学生在小程序里除了交作业，还要能看到关于"我"的一切：

- **排名体系**：
  - 班级排名（我在班里第几）
  - 年级排名（我在年级第几）
  - 省/全国排名：基于已接入本产品的学校数据计算，不是所有学校都参与。
  - **参与学校地图/列表**：在小程序里清楚展示哪些省份、哪些城市的学校参与了跨校排名；学校可选择是否参与。
  - 排名变化趋势：这周比上周升了还是降了。
- **我的成绩**：各科成绩单、总分、进步曲线（折线图）。
- **我的纪律分**：被警告过几次、扣了几分、当前纪律分多少。
- **我的课表**：今天/本周/明天上什么课。
- **我的错题本**：自动归集的错题，考前可刷。
- **我的薄弱点**：哪些知识点总是错，AI 推荐补什么。
- **我的辅导记录**：近期问了什么问题、AI 答了什么。
- **我的请假进度**：申请批了没。
- **学习目标**：本阶段目标（如"数学下次考到 85"），完成度可视化。

### 3.28 家长端增强

**家长在小程序上除了看数据，还要有互动感：**

- **课堂互动详情**：孩子今天举了几次手、被点名几次、答对几题、被问了几次——不只是一个表现分数字。
- **孩子情绪状态**：AI 通过表情识别，反馈这节课孩子整体情绪（专注/无聊/沮丧/开心），后十分钟状态如何。
- **即时异常推送**：不只是每日报告，而是实时推送——"您孩子数学课被点名批评""这节课趴桌 15 分钟"。
- **AI 评语原文**：不只是分数，AI 老师具体写了什么评语，家长能逐字看。
- **完整成长档案**：从入学到现在的成绩曲线、纪律记录、进步轨迹。
- **校园通知**：家长会、放假、学校活动在小程序推送，不用班级群爬楼。
- **学科对比详情**：不只是排名，而是"数学高于班级均分 5 分，语文口语偏弱"。
- **家长留言与课堂转达**：
  - 家长在小程序给孩子留言（"今天加油""注意身体"）。
  - 留言在该学生所在课堂上，由 AI 老师当面转达："XX，你妈妈想对你说，今天加油。"
  - 也可由任课老师/管理员筛选哪些留言要公开转达，避免不合适内容进课堂。

### 3.29 成绩报告分享与品牌传播（增长功能，重点）

**目标：让学生、家长、学科老师、校长都愿意把成绩转发朋友圈，点开不用登录就能看，既是他们的成就感，也是产品免费广告。**

**分享层级（从个人到全校）：**
- 学生：分享自己的进步和评估
- 家长：分享孩子的成长
- 学科管理教师：分享本科本年级汇总，或某个班的具体成绩
- 校长：分享整个学校、某年级、某班级的整体成果

**分享打开方式（微信生态内闭环）：**
- 从小程序分享到朋友圈/微信群，好友点开**直接打开小程序**，看到对应分享页，不跳 H5 网页。
- 分享页**不需要登录**就能浏览全部公开内容（登录就没人点了）。
- 小程序底部带"了解 AI Teacher / 预约演示"入口，扫码或点击可留资。

**页面内容要丰富：**
- **排名体系全维度**：班级排名、年级排名、县城排名、城市排名、省排名、全国排名。
- **综合评估**：不只一个分数，多维度展示——课堂表现、作业、考试、纪律、参与度。
- **进步趋势**：折线图展示最近几次考试/几次课的变化。
- **亮点标签**："本月进步最大""数学班级前 5""连续四周全勤"。
- **学校/班级整体**：校长或老师分享时，展示全校/全年级/全班平均分、及格率、排名对比。
- 所有数据配简洁图表，视觉化，不堆数字。

**分享方式：**
- 小程序内一键生成海报长图，保存到相册或直接发朋友圈/微信群。
- 也可生成 H5 链接，点开即看。

**隐私与安全：**
- 默认只展示正面/亮点数据，负面信息不进分享页。
- 学校可全局开关此功能、控制哪些维度可对外公开。
- 学生真实姓名可配置为昵称/小名。
- 页面必带产品水印和二维码，扫码可了解产品、预约演示。

**传播效果**：每个转发都是一次免费曝光，点开即获客入口。

**产品经理补充（8 条）：**

1. **分享内容边界**：全班/全年级分享时，默认只展示聚合数据和亮点（平均分、及格率、前 10 名、进步最大），**不展示完整排名名单**，避免排后面的家长投诉。具体学生姓名只在分享自己孩子/自己时出现。

2. **触发时机**：不每节课都弹。只在有亮点时主动提示——"你孩子月考进步 5 名""本月课堂表扬 8 次"。学生/家长有动力才分享，平时不打扰。

3. **点开后转化闭环**：外校访客看完成绩，页面底部有明确 CTA——一键预约演示、留电话、扫码加微信。这是获客漏斗，不是纯展示页。

4. **快照机制**：分享那一刻生成永久快照（当时成绩、排名、图表），老链接不会因为后续数据变化而变。

5. **传播数据看板**：学校可见本校被分享次数、外部访客数、留资数；你后台看哪个学校分享最多、带来多少线索。

6. **合规与授权**：学生成绩对外公开需家长可授权/可关闭；分享页底部带隐私说明；学校可全局开关此功能。

7. **品牌主次**：分享页学校 logo 和校名最大，产品水印放角落。让学校觉得在晒自己的教学成果，不是在帮你打广告。

8. **冷启动**：新学校无历史数据时，分享页展示过程数据（已上课数、平均举手次数、作业完成率、出勤率），不硬编成绩。

### 3.30 各方补充需求

**校长/学校视角：**
- **教育局检查一键导出**：上课录像、纪律记录、教学质量报告一键打包导出，应付教育局检查。
- **现有硬件复用**：学校已有投影/电脑不强求换新，小盒子只是加进去兼容。
- **产品优势直给**：给校长看的报表直接突出"替代了多少老师、省了多少人力成本"，不做老师安抚。

**年级主任/学科老师视角：**
- **AI 教案后台可编辑**：老师能改 AI 做的 PPT 和讲稿，改完 AI 按改后内容上课。
- **旁听时实时纠正 AI**：老师旁听发现讲错了，能打断纠正。
- **工作量对比**：用 AI 前后备课、批改时间自动对比。

**家长视角：**
- **近视提醒**：每 40 分钟提醒学生休息。
- **AI 批评后自动说明**：AI 批评孩子后自动给家长发消息解释原因，避免孩子回家挨骂。
- **隐私开关**：家长可选择关闭自己孩子成绩对外分享。

**学生视角：**
- **桌位求助键**：除了举手，按一下桌位上的按钮就求助。
- **学习节奏可调**：AI 讲太快/太慢，学生能自己调。
- **AI 风格可选**：严肃/温柔/幽默，学生选喜欢的。

**Super 管理员视角：**
- **用量监控**：每个学校 API token 用量，超支告警。
- **学校健康度**：活跃度下降预警，防流失。
- **远程升级**：学校客户端自动更新，你远程推送。

### 3.31 家长满意度问卷

- **触发时机**：每学期末自动推送给家长小程序。
- **问卷内容**：
  - 对 AI 老师整体满意度（1~5 星）
  - 课堂互动是否充分
  - 作业批改是否及时准确
  - 孩子成绩是否有提升
  - 孩子是否愿意上 AI 课
  - 开放反馈栏（文字建议）
- **结果汇总**：
  - 按班级、年级、全校维度汇总
  - 满意度趋势对比
  - 低分预警：某个班满意度低于阈值自动通知学校管理员
- **你的后台**：所有学校满意度对比，作为产品改进和续费参考。

### 3.32 多校区/分校管理

- **集团总部视角**：Super 管理员可创建多个校区，跨校区汇总数据。
- **校区独立**：每个校区有自己的排课、教材、教师、学生、成绩数据，互不干扰。
- **跨校区汇总**：集团可看各校区对比、整体成绩、整体满意度。
- **权限**：
  - 集团管理员：看所有校区，不能改单校区教学内容
  - 校区管理员：只管本校区
- **计费**：按学校年订阅（费用按校区或按教室数核算），集团签一个总合同。

### 3.33 AI 备课流程（细化）

1. **教材上传**：老师上传电子版教材（PDF/Word/扫描版）。
2. **教材解析**：
   - 文字版：直接提取章节、目录、正文
   - 扫描版：本地 PaddleOCR 识别
3. **大纲生成**：AI 按教材拆出教学大纲（每章几课时、重点难点）。
4. **教案生成**：每节课生成 PPT 大纲 + 讲稿 + 课堂提问 + 课后作业建议。
5. **老师确认**：老师在后台看到 AI 生成的所有教案，可编辑、可删除、可调整。
6. **锁版**：老师确认后锁版，到上课时间 AI 按锁版内容讲，课中实时互动。

### 3.34 AI 作业批改流程（细化）

1. **作业生成**：AI 按教案和知识点生成作业，老师确认后下发。
2. **学生提交**：小程序拍照/文字提交。
3. **AI 批改**：
   - 客观题（选择/填空）：自动判分
   - 主观题（作文/论述）：AI 初评打分 + 写评语
   - 计算题：识别步骤，按步骤给分
4. **老师复核**：主观题进入复核工作台，老师逐条改分、写评语、通过。
5. **成绩回写**：自动写入数据库，学生和家长可看。
6. **错题归集**：自动进学生错题本。

### 3.35 AI 监考与考试流程（细化）

1. **考前**：
   - 老师组卷 → 审卷 → 锁卷
   - 到考试时间自动分发到学生端/教室大屏
2. **考中**：
   - 摄像头实时监控：低头看资料、传纸条、转头看旁边
   - 麦克风检测：异常说话声
   - 发现作弊：自动记录时间和画面，当场提醒
3. **考后**：
   - 客观题自动判分
   - 主观题 AI 初评 + 老师复核
   - 生成考试分析：平均分、及格率、薄弱知识点、班际对比

### 3.36 辅导模式细化

- **学生端**：戴智能眼镜（看题/看手写）+ 耳机/麦克风（听说）。
- **连接方式**：学生在小程序点"开始辅导"，云端辅导 Agent 接入。
- **辅导流程**：
  1. 学生说"这题不会"或指眼镜看题
  2. 眼镜画面+声音传到云端
  3. AI 识别题目 → 讲解 → 回答追问
  4. 辅导结束出即时评估
- **时间限制**：按学校套餐配置每人每天辅导时长。

### 3.37 学生端体验增强

**① 桌位求助键**
- 每个学生桌上装一个物理按钮（USB/蓝牙连小盒子）
- 学生按一下 → 小盒子立刻上报"XX 桌位求助"
- 数字人转向该学生："这位同学有什么问题？"
- 学生不用举手，按按钮就行，比举手更灵敏
- 硬件：USB 自定义按钮（淘宝搜"USB 自定义按键"，约 ¥20~30/个）
- 对接：小盒子通过 HID 协议读取按键事件，上报云端

**② 近视提醒**
- 每节课上课满 40 分钟，数字人自动说："同学们休息一下，闭上眼睛远眺 30 秒"
- 同时屏幕上显示"休息一下，保护视力"的提示
- 提醒频率：每 40 分钟一次，一节课 45 分钟就提醒一次
- 家长端可查看孩子这节课有没有按提醒休息
- 管理员可配置提醒时长和频率

**③ 学习节奏可调**
- 学生在小程序个人中心可调 3 个参数：
  - **讲解速度**：慢/正常/快（对应 TTS 语速 0.8x / 1.0x / 1.2x）
  - **重复次数**：重点知识点要不要再讲一遍
  - **提问难度**：简单/中等/挑战（AI 提问时按这个难度出题）
- 调整后该学生上所有 AI 课都按他的偏好来
- 老师可看全班节奏分布，发现大多数学生都觉得快了就整体调慢

**④ AI 风格可选**
- 学生在小程序个人中心选 AI 老师的语气风格：
  - **严肃型**：语速快、表情严肃、纪律要求严
  - **温柔型**：语速适中、语气温和、多鼓励
  - **幽默型**：语速适中、会讲笑话、气氛活跃
- 调整后该学生的 AI 课按他选的风格上
- 管理员可按科目默认风格（如数学严肃、语文温柔），学生可覆盖默认
- 数字人表情和手势也随风格变化

### 4.2 SaaS 部署架构（商业模式决定）

**核心原则：你的核心 IP（Skill 规则、教学流程、Agent 提示词、数字人模型）全部在你的云服务器上，学校端只装瘦客户端。**

```
[你的云服务器]
  · 核心 AI 能力与 Skill 引擎（不外露）
  · Agent 调度、数字人渲染、教学流程
  · 学校订阅管理、计费
  · 小程序后端、家长看课转流

[学校管理端（学校管理员在办公室用，浏览器访问）]
  · 连你的云，用学校账号登录
  · 排课、传教材、看报表、作业审批
  · 管理本校所有教室小盒子

[教室小盒子（树莓派5，在每间教室里）]
  · 连你的云，到点自动启动上课
  · 本地跑视觉模型+ASR+TTS
  · HDMI 接投影、USB 接摄像头麦克风
  · 课前预热下载 PPT+讲稿到本地

[微信小程序] → 连你的云，按学生/家长/教师模式分发
```

### 4.3 物理网络

- 学校机房/办公室：核心交换机（管理端用浏览器访问，不用装软件）。
- 每年级/每层楼：楼层交换机（标记年级）。
- 每间教室：墙上网线口 → 小盒子 → HDMI 接投影、USB 接摄像头麦克风。
- 网线同时传：云→教室的上课画面，和教室→云的学生音视频。

### 4.4 非功能需求

- **跨平台**：管理后台 Chrome/Edge 浏览器即可；教室端跑树莓派 5；小程序微信原生。
- **必须联网（IP 保护）**：核心 Agent、Skill、教学流程全在云端。**启动时必须在线鉴权**，无有效订阅或断网则拒绝启动。已启动的课如果中途断网，可按预热内容讲完，即兴互动降级。
- **客户端防破解**：学校端软件加壳混淆、反调试、反虚拟机；核心逻辑永不落地到学校；即使客户端被反编译也拿不到教学大脑。
- **数据归属**：学生数据归学校；你的云做处理和转发，订阅到期可清除。
- **隐私**：家长按绑定关系鉴权，只能看自己孩子；人脸数据加密存储。
- **并发**：支持一个学校 50 个教室同时上课，单校 2000 学生同时用小程序。
- **性能指标**：
  - API 接口平均响应 < 200ms
  - 教室端启动到鉴权完成 < 5 秒
  - 家长看课直播延迟 < 3 秒
  - 举手识别→AI 响应 < 5 秒
  - 小程序冷启动 < 2 秒
- **可用性**：全年可用率 99.5%（每月计划内停机 < 3.6 小时）
- **兼容性**：
  - 管理后台：Chrome/Edge 最新两个版本
  - 小程序：微信 8.0+
  - 教室端：树莓派 Raspberry Pi OS 64-bit
- **数据保留**：课堂录像保留 90 天，成绩和评估永久保留，行为日志保留 1 年
- **数据备份**：PostgreSQL 每日自动备份，保留 30 天；MinIO 每日增量备份；备份异地存储

### 4.4.1 客户端升级机制

- **自动更新**：学校客户端启动时检查新版本，后台静默下载，下次启动生效
- **强制更新**：有安全补丁或破坏性变更时，弹窗提示必须更新才能使用
- **回滚**：更新失败自动回退到上一版本
- **灰度**：先给 1~2 所学校推送新版本，观察一周再全量

### 4.4.2 异常场景处理

| 场景 | 处理 |
|---|---|
| AI 讲错知识 | 老师旁听可打断纠正；教案需老师确认才生效 |
| LLM API 挂了 | 自动切备用供应商（DeepSeek→豆包→GLM） |
| 小盒子蓝屏 | 自动重启；5 分钟起不来告警后勤 |
| 投影没信号 | 教室屏幕显示"设备连接异常"，同时告警管理员 |
| 学生请假未同步 | 请假状态在云端实时同步，小盒子每 5 分钟拉一次 |
| 微信小程序审核被拒 | 提前准备审核材料；保留 H5 备用入口 |

**请假类型**：事假 / 病假 / 公假 / 其他
**请假状态**：待审批 / 已通过 / 已驳回 / 已撤销
**纪律事件**：说话 / 走动 / 睡觉 / 旷课 / 迟到 / 早退 / 举手 / 趴桌 / 离座 / 低头看手机
**作业状态（作业单 assignments）**：草稿 / 待确认 / 已下发 / 已截止
**作业状态（提交单 submissions）**：已提交 / AI批改中 / 待复核 / 已完成
**考试类型**：月考 / 段考 / 期末 / 模拟 / 随堂
**订阅状态**：试用中 / 有效 / 即将到期 / 已过期 / 已停用

### 4.5 断网兜底方案（已定）

原则不变：核心 Agent、Skill、提示词永不落地学校，断网后核心智能不可用。

- **双链路兜底（已选）**：教室主网线断了，客户端自动切换到 4G/5G 备用上网卡，保证核心服务连通。切换过程无感知。
- **开机网络预检（随双链路）**：客户端启动先测云连通性并检测双链路状态，不通立即告警管理员，留出换网/调课时间。
- **课前预热缓存（已选）**：上课前 10 分钟把本节课 PPT+讲稿下载到小盒子本地（见 4.7）。云挂了至少能按稿讲完，即兴互动降级。

### 4.6 部署与成本最优方案

**核心原则：不自建 GPU 大模型，重活在教室本地做，云只做调度和分发。**

**① 模型调用策略（不自建模型，全调第三方 API）**

| 能力 | 方案 | 成本 |
|---|---|---|
| LLM 教学对话 | 调 DeepSeek / 豆包 / GLM API（后台可配置切换，按成本择优） | 按 token 计费 |
| 语音识别 ASR | **本地跑 Whisper.cpp**（教室端） | 零 API 费 |
| 语音合成 TTS | **双路**：按稿讲本地跑（piper/edge-tts），即兴互动调腾讯云 TTS | 按字符计费（仅即兴） |
| 视觉识别（人脸/举手/行为） | **教室本地跑 OpenCV + ONNX 模型** | 零 API 费，省上行带宽 |
| OCR | **本地跑 PaddleOCR**（开源） | 零 API 费 |
| 数字人渲染 | **教室前端 Live2D 组件本地渲染**，TTS 音频驱动口型 | 零 GPU |

**关键：上课画面不在云端渲染。** PPT 和数字人都是教室客户端的前端组件，云端只发"翻到第3页、说这段话"的指令，教室本地渲染。云端不需要 GPU、不转视频。

**② 带宽分配（最大成本项）**

- **课中 AI 识别**：教室摄像头本地做人脸检测/举手/违纪判断，**只上传"谁在哪个座位做了什么"这种结构化事件**，不传视频流上云。
- **家长看课**：教室客户端推一路视频流到云直播服务，CDN 分发给家长手机。只在家长在线观看时产生流量。
- **学生音视频**：学生说话经本地 ASR 转成文字后上传，不传原始音频。

**③ 服务器与组件选型（能自己实现的不买，只买必须的）**

| 组件 | 方案 | 说明 |
|---|---|---|
| 应用服务器 | **腾讯云 CVM** 8核16G × 2~3 台 | 跑后端 API、Agent 调度、鉴权 |
| 数据库 | **腾讯云 TencentDB PostgreSQL** | 托管数据库，省心 |
| 缓存/消息 | **自己跑 Redis**（装在 CVM 上） | 开源免费，不买托管 |
| 对象存储 | **自己跑 MinIO**（开源，装 CVM 上） | 主存储不买 COS（教材/录像存自建 MinIO）；仅异地备份按量用腾讯云 COS（见 21.12） |
| 直播分发 | **自己跑 SRS**（开源流媒体）装在 CVM 上 | 不买 CSS，家长看课走 SRS |
| 人脸识别/行为识别 | **本地跑 OpenCV + ONNX 模型** | 教室小盒子上跑，不买云人脸 API |
| ASR 语音识别 | **本地跑 Whisper.cpp** | 教室本地转文字，不买云 ASR |
| OCR | **本地跑 PaddleOCR**（开源） | 教材/手写作业识别，不买云 OCR |
| 内容审核 | **本地关键词+规则过滤**，必要时调云审核 | 初期自己写过滤规则 |
| TTS 语音合成 | **双路**：本地 piper/edge-tts（按稿讲）+ 腾讯云 TTS（即兴，买 3 个声音授权） | 按稿讲零费，即兴按字符计费 |
| LLM | **调 DeepSeek / 豆包 / GLM API** | 必须买，不自建大模型 |
| 短信通知 | **腾讯云 SMS** | 必须买，国内短信通道 |
| 微信服务通知 | **微信原生接口** | 免费 |
| 部署 | **Docker Compose** | 自己跑，不买 K8s（初期） |

**原则：能开源自建的全部自建（Redis/MinIO/SRS/PaddleOCR/Whisper/视觉模型），只买必须的（CVM 云主机、PostgreSQL 托管、TTS 声音、短信通道、LLM API、异地备份存储（腾讯云 COS 按量，见 21.12））。初期 2~3 台 CVM 就能跑起来。**

**④ 成本结构**
- 一次性：无（全部云服务按需付费）
- 主要持续成本：API 调用费（LLM/ASR/TTS）+ 云服务器 + 存储 + CDN 流量
- 不买 GPU、不建机房、不养运维团队，初期 2~3 台云主机就能跑起来

### 4.7 故障降级与本地缓存策略（架构修正）

**修正 1：小盒子和教室客户端合并**
树莓派 5 本身就跑 Electron（或轻量 WebView）+ 本地视觉模型 + 本地 ASR，不需要分开两个设备。一个教室就是一台小盒子，HDMI 接投影、USB 接摄像头麦克风。

**修正 2：课前预热下载**
- 上课前 10 分钟，小盒子自动从云端下载本节课的全部 PPT 图片、讲稿、教案到本地缓存。
- 上课过程中按稿讲的内容全部从本地读，不实时拉云端。
- 云挂了至少能按稿讲完整节课，即兴互动功能降级但课能上完。

**修正 3：TTS 本地跑**
- 非即兴场景（按稿讲）：TTS 在小盒子本地跑（piper/edge-tts），零延迟，零 API 费。
- 即兴互动场景（学生举手提问后 AI 现场解答）：调云端 TTS（腾讯云），保证自然度。
- 两种 TTS 自动切换，学生无感知。

**修正 4：LLM 调用优化**
- 按稿讲阶段：不调 LLM，直接读课前生成好的讲稿。
- 只有举手/提问/纪律事件发生时才调 LLM。
- 大幅降低 token 消耗。

## 五、商业模式与官网

### 5.1 收费模式

- **统一学校订购**：只有学校能订阅，家长不能单独购买。

- **辅导也收费**：24 小时辅导能力包含在学校订阅内（寒暑假可低成本额外开通），不向家长单独收。

2. **四方痛点**（不讲废话，直接说解决谁的问题）：

## 十、数据指标定义

### 10.1 课堂参与分（每节课）
= 举手次数×2 + 被点名答对×3 - 被警告次数×1（原始分）
满分 100：满分档位 = 举手5次 + 答对2题 + 0警告 = 16 原始分，实际得分 = 原始分 ÷ 16 × 100，封顶 100

### 10.2 纪律分（初始100分）
- 大声说话：-5
- 离座/走动：-3
- 睡觉/趴桌：-8
- 旷课：-20
- 迟到：-5
- 全勤：+5

### 10.3 教学质量分（每节课）
= 互动率×40% + 学生注意力×30% + 作业完成率×20% + 举手频次×10%
- 互动率：回答问题人数/全班人数
- 学生注意力：摄像头检测专注人数/全班人数
- 作业完成率：交作业人数/全班人数

### 10.4 综合评估分（每月）
= 课堂参与×25% + 纪律分×25% + 作业成绩×25% + 考试成绩×25%

### 10.5 班级课堂氛围分
= (安静时长×2 + 举手次数×1 - 嘈杂时长×3) / 总时长
0~100，越高越好

## 二十一、数据库设计规范（数据库工程师视角）

### 21.1 数据库选型
- **主库**：PostgreSQL 16（腾讯云托管）
- **缓存**：Redis 7（自建）
- **对象存储**：MinIO（自建）
- **搜索引擎**：暂不用，后期上 Meilisearch

### 21.2 表设计规范

**主键策略**：
- 所有表用 id BIGINT PRIMARY KEY GENERATED ALWAYS AS IDENTITY（自增长整型）
- 业务唯一索引单独建（如 student_no、(student_id, openid)）

**审计字段（每个表必须有）**：
- created_at TIMESTAMPTZ DEFAULT NOW()
- updated_at TIMESTAMPTZ DEFAULT NOW()
- created_by BIGINT（操作人）
- updated_by BIGINT

**软删除**：
- 所有业务表加 deleted_at TIMESTAMPTZ NULL
- 查询默认 WHERE deleted_at IS NULL

**字段命名**：
- 全小写下划线，如 student_id
- 时间字段统一 _at 后缀
- 布尔字段统一 is_ / has_ 前缀
- 金额用 NUMERIC(10,2)，不用 FLOAT

### 21.3 索引策略

**必须建索引的字段**：
- 所有外键（student_id, class_id, room_id, assignment_id）
- 常用查询条件（status, school_id, subject_id）
- 时间范围查询（start_at, end_at, created_at）

**联合索引示例**：
- behavior_events(room_id, student_id, created_at) — 查某教室某学生某时间事件
- submissions(assignment_id, student_id) — 查某作业某学生提交
- scores(exam_id, student_id) — 查某考试成绩

**唯一索引**：
- users(school_id, phone) — 同校手机号唯一
- students(school_id, student_no) — 同校学号唯一
- parents(student_id, openid) — 一个学生一个家长绑定

### 21.4 大表分表策略

**会超大的表**：
- behavior_events（每节课每教室几十条事件）
- lesson_records（每节课一条记录）
- evaluations（每节课每学生一条评估）

**分表方案**：
- 按学校分 schema：school_001、school_002
- 或按月分区：behavior_events_2026_09
- 初期不分表，单校 2000 学生数据量不大

### 21.5 读写分离
- 主库：写操作（INSERT/UPDATE/DELETE）
- 从库：读操作（SELECT）
- Prisma 配置：读走从库，写走主库
- 初期单库，后期量大再加从库

### 21.6 数据归档
- 课堂录像元数据：90 天后从主库归档到冷表
- 行为日志：1 年后归档
- 成绩和评估：永久保留
- 归档用定时任务（BullMQ 每日跑）

### 21.7 JSONB 字段使用
- 教案内容：content JSONB（结构化存章节、讲稿、提问）
- 评估报告：
report JSONB（多维评估结果）
- 课堂事件详情：detail JSONB
- JSONB 上建 GIN 索引支持查询

### 21.8 数据库连接池
- 最大连接数：50（单实例）
- 空闲连接：10
- 连接超时：5 秒
- 查询超时：30 秒

### 21.9 迁移工具
- 用 Prisma Migrate 管理表结构变更
- 每次改表写一个 migration 文件
- 生产环境 prisma migrate deploy
- 禁止手动改表结构

### 21.10 慢查询优化
- 开启 PostgreSQL 慢查询日志（阈值 100ms）
- 每周分析慢查询 Top 10
- 禁止 SELECT *，只查需要的字段
- 大查询走只读从库

### 21.11 数据库监控
- 监控指标：连接数、QPS、慢查询数、磁盘使用率、复制延迟
- 告警阈值：连接数 > 80%、慢查询 > 10 条/分钟、磁盘 > 80%
- 工具：Prometheus + Grafana

### 21.12 备份恢复
- 每日全量备份：保留 30 天
- 每小时 WAL 归档：支持时间点恢复
- 每月做一次恢复演练
- 备份异地存储（腾讯云 COS，按量付费，仅备份用途；与 4.6 自建 MinIO 主存储不冲突）

## 二十二、运维手册（运维工程师视角）

### 22.1 服务器初始化

**新 CVM 上线步骤**：
1. 腾讯云买 CVM（Ubuntu 22.04，8核16G）
2. 安全组开放端口：22(SSH)、80(HTTP)、443(HTTPS)、1935(RTMP)、8080(SRS)
3. 创建部署用户：adduser deploy
4. 安装 Docker：curl -fsSL https://get.docker.com | sh
5. 安装 Docker Compose：apt install docker-compose-plugin
6. 配置防火墙：ufw allow 22,80,443,1935,8080
7. 安装 Node.js 20：curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt install nodejs
8. 安装 Git：apt install git

### 22.2 部署流程

**首次部署**：
`

cd aiteacher
cp .env.example .env

docker-compose exec backend npx prisma migrate deploy

### 22.3 日志规范

**日志级别**：
- ERROR：业务错误、接口失败
- WARN：可恢复的异常、重试
- INFO：关键业务节点（上课开始/结束、作业提交）
- DEBUG：开发用，生产关闭

**日志文件**：
- Nginx 日志：/var/log/nginx/
- 应用日志：docker logs aiteacher-backend
- SRS 日志：/var/log/srs/
- 系统日志：/var/log/syslog

**日志保留**：
- 应用日志保留 30 天
- Nginx 访问日志保留 90 天
- 错误日志永久保留

### 22.4 故障应急手册

**场景 1：后端服务挂了**
- 现象：接口 502
- 处理：docker-compose ps 看状态 → docker-compose logs backend → docker-compose restart backend

**场景 2：数据库连不上**
- 现象：接口报 ECONNREFUSED
- 处理：检查 TencentDB 控制台 → 检查安全组 → 检查连接数

**场景 3：教室小盒子离线**
- 现象：监控告警某教室 5 分钟无心跳
- 处理：联系学校后勤检查网线/电源 → 远程 ping 测试 → 备用小盒子替换

**场景 4：LLM API 调用失败**
- 现象：学生举手 AI 不响应
- 处理：自动切备用供应商 → 手动检查 API 余额 → 联系供应商

**场景 5：磁盘满了**
- 现象：告警磁盘 > 80%
- 处理：清理日志（docker system prune）→ 清理旧录像 → 扩容云硬盘

**场景 6：直播看不了**
- 现象：家长小程序看课黑屏
- 处理：检查 SRS 服务 → 检查小盒子推流 → 检查 CDN 带宽

### 22.5 监控告警配置

**监控项**：
- 服务器 CPU/内存/磁盘/带宽
- Docker 容器状态
- PostgreSQL 连接数、QPS、慢查询
- Redis 内存命中率
- Nginx 请求量、错误率
- 小盒子在线率
- LLM API 调用成功率
- 每日费用统计

**告警通道**：
- 企业微信机器人（工作时间）
- 短信（P0 故障，24 小时）
- 邮件（日报/周报）

**告警阈值**：
- CPU > 80% 持续 5 分钟
- 内存 > 85% 持续 5 分钟
- 磁盘 > 80%
- 接口错误率 > 5%
- 小盒子离线 > 5 分钟

### 22.6 扩容方案

**什么时候扩容**：
- 单校超过 100 个教室 → 加应用服务器
- 数据库 QPS > 1000 → 加只读从库
- 直播带宽 > 100Mbps → 加 CDN 节点

**怎么扩容**：
- 应用：加一台 CVM，Docker Compose 复制，Nginx 负载均衡
- 数据库：腾讯云控制台直接升配
- 存储：加云硬盘挂载

### 22.7 安全加固

**服务器**：
- 禁用 root SSH，用普通用户+密钥登录
- SSH 端口改非 22
- 自动安全更新：apt unattended-upgrades
- 关闭不必要的端口

**应用**：
- HTTPS 全站（Let's Encrypt 证书）
- 接口限流（Nginx + Redis）
- 敏感环境变量不进 Git
- 依赖包定期更新（npm audit）

**数据**：
- 数据库定期备份
- 人脸数据加密存储
- 操作日志留存 1 年

### 22.8 成本优化

## 二十五、教室端部署与升级方案

### 25.1 首次部署（烧录镜像）
1. 我们这边做好一个 SD 卡镜像：
   - Raspberry Pi OS（树莓派系统）
   - 预装 Electron 教室端应用
   - 预装本地模型（视觉/ASR/TTS）
   - 配置开机自启动、全屏、双链路
2. 用烧录工具写到 SD 卡里
3. 学校拿到树莓派，插卡插电开机就能用
4. 第一次开机自动联网鉴权，绑定到学校

### 25.2 日常升级（不用换卡）
**应用自动更新（像 VS Code 一样）：**
1. 教室端启动时自动检查新版本
2. 有新版本 → 后台静默下载
3. 下次上课前自动安装
4. 重启后生效

**升级策略：**
- **小更新**：静默更新，不打扰
- **大版本**：弹窗提示"有新版本，明天上课前自动更新"
- **强制更新**：有安全补丁时，必须更新才能用
- **回滚**：更新失败自动回退到上一版本

### 25.3 升级流程
1. 我们在公司后台发布新版本
2. 选择推送哪些学校（灰度先推 1~2 所）
3. 教室端开机检查，下载更新包
4. 上课前 30 分钟自动安装
5. 安装完成重启，新版本生效
6. 失败自动回滚，继续用旧版本

### 25.4 系统镜像什么时候换？
- 只有大版本升级（比如换了新系统、加了新硬件驱动）才需要换 SD 卡
- 平时应用更新不用换卡，远程自动更新就行
